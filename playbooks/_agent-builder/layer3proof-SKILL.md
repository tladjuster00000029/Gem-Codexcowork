# 목적
`[job-name]/SKILL.md`에 객관적 증거 기반의 '완료의 정의(검증 항목)'를 추가하고, 업무 수행 시 결과물 제출 전 자체 검증을 강제한다.

# 언제 쓰는지
내가 "레이어 3: 완료의 정의 추가해" 또는 업무 실행 후 "검증 돌려"라고 말할 때 실행한다.

# 실행 순서
1. `[job-name]/SKILL.md`의 `완료의 정의` 섹션에 이 업무에 특화된 검증 항목 5~10개를 작성해라.
   - 모든 항목은 AI의 주관적 의견 바깥의 증거로 확인 가능해야 한다 (원본 파일까지 추적되는 숫자, 열리는 링크, 테스트 통과 여부, 인용문 대조, 단어/글자 수, 참조 파일과의 표기 일치 여부).
   - "명확한", "전문적인", "고품질의", "자연스러운" 같은 모호한 형용사는 절대 쓰지 마라.
2. 앞으로 이 업무를 마칠 때마다 나에게 결과물을 보여주기 전에 다음 5단계를 수행해라:
   - ① 모든 검증 항목을 돌린다.
   - ② 실패한 항목을 스스로 고친다.
   - ③ 검증을 다시 돌린다.
   - ④ 항목마다 `[통과/실패] + 실제 근거`를 한 줄씩 출력한다.
   - ⑤ 확인할 수 없는 항목은 통과로 가정하지 말고, 무엇을 왜 확인할 수 없는지 명시한다.
3. 만약 첫 번째 패스에서 2개 초과의 항목이 실패하면, 결과물을 억지로 땜질하지 말고 즉시 멈춘 뒤 어느 프로세스 단계가 원인이었는지 보고해라.

# 파일 저장 및 교체 규칙 (필수 동의 절차)
- 파일을 직접 쓸 수 없다면 쓴 척하지 마라.
- 업데이트된 `[job-name]/SKILL.md` 전체 내용과 정확한 저장 경로를 출력해라.
- 출력 후 **"완료의 정의 업데이트에 동의하십니까? 동의하시면 로컬 폴더의 `SKILL.md`를 덮어쓰고 프로젝트의 예전 복사본을 지운 뒤 새 파일로 교체해 주세요."**라고 동의를 구해라.
