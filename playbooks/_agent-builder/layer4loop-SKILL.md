# 목적
산출물이 틀렸을 때 채팅창에서 임시방편으로 고치는 대신, 실패한 레이어를 진단하여 `SKILL.md`나 툴박스를 영구 수정하고 `notes.md`에 기록한다.

# 언제 쓰는지
내가 "레이어 4: 결과물이 틀렸다. 이유는 [구체적인 오류 내용]"이라고 말할 때 실행한다.

# 실행 순서
1. 먼저 아래 세 가지 중 어느 레이어가 실패했는지 진단하여 정확히 두 문장으로(어느 레이어인지 + 왜 실패했는지) 말해라:
   - 프로세스 실패: 단계가 빠졌거나, 순서가 틀렸거나, 결정 뒤의 규칙이 적히지 않았다.
   - 툴박스 실패: 이미 있는 도구를 안 쓰고 백지에서 다시 지었거나, 저장된 파일이 낡았거나 틀렸다.
   - 증명 실패: 이 오류를 잡아냈어야 할 검증 항목이 `완료의 정의`에 존재하지 않는다.
2. 매뉴얼 전체를 다시 쓰지 말고, 해당 레이어에 가장 작고 내구성 있는 수정을 가해라.
   - 단, 같은 실수가 두 번 이상 반복되었다면 부드러운 주의사항이 아니라 이를 원천 차단하는 명시적 금지/강제 규칙을 추가해라.
3. `[job-name]/notes.md`의 맨 윗줄(최신이 위로 오게)에 추가할 한 줄(`YYYY-MM-DD | 무엇이 잘못됐는지 | 무엇을 바꿨는지`)을 작성해라.
4. 같은 작업을 처음부터 다시 돌려서 **[수정 전 결과]와 [수정 후 결과]**를 나란히 비교해 보여줘라.

# 파일 저장 및 교체 규칙 (필수 동의 절차)
- 파일을 직접 쓸 수 없다면 쓴 척하지 마라.
- 수정된 파일(`SKILL.md` 또는 툴박스 파일)의 전체 내용과 `[job-name]/notes.md` 전체 내용, 정확한 폴더 경로를 출력해라.
- 출력 후 **"이 매뉴얼 수정안에 동의하십니까? 동의하시면 내 컴퓨터 폴더의 파일을 교체하고, 프로젝트에 업로드된 예전 복사본을 삭제한 뒤 새 파일로 업로드해 주세요."**라고 동의를 구해라.
