# 매번 OTP로 변경 승인하기

기본 정책은 모든 변경에 OTP입니다. 중요도가 낮다는 이유로 자동 전환하지 않습니다. 나중에 사용자가 정책 변경을 요청한 경우 별도 변경으로 진행합니다.

## 구현 범위와 남은 설정

로컬 승인 도구는 OTP 없이 병합하지 않습니다. 하지만 도구를 설치한다고 GitHub의 일반 Merge 버튼이나 관리자 권한까지 차단되는 것은 아닙니다. 저장소 전체에 강제하려면 기본 브랜치의 직접 push·일반 사용자 병합을 제한하고, 별도 병합 전용 GitHub App과 검증된 OTP 승인 경로에만 병합 권한을 부여하는 보호 규칙을 적용해야 합니다. 저장소의 권한·요금제·인증이 아직 확인되지 않아 그 보호 설정은 미적용입니다. 설정 전에는 전체 저장소의 우회 방지가 완성됐다고 간주하지 마세요.

## 준비

1. Node.js 24를 설치하고 저장소 파일을 내려받습니다.
2. GitHub에서 본 저장소에만 접근하는 만료일이 있는 fine-grained token을 직접 만듭니다. Contents: Read and write, Pull requests: Read and write, Checks: Read, Commit statuses: Read 권한이 필요합니다. 토큰을 코드·채팅·Actions 입력란에 넣지 마세요. 토큰 발급은 본인이 직접 승인해야 합니다.
3. Windows에서는 `open-approval.cmd`를 더블클릭합니다. 또는 저장소 폴더에서 `node approval/server.mjs`를 실행합니다 (`npm run approve`도 가능).
4. 표시된 `http://127.0.0.1:…` 주소를 이 컴퓨터 브라우저에서 엽니다. 외부에 공개하거나 터널로 연결하지 마세요.

## 처음 한 번

승인 화면에서 GitHub 토큰을 입력해 연결합니다. 토큰은 프로세스 메모리에만 보관하며 종료하면 사라집니다.

“등록용 설정 키 만들기”를 본인이 누른 후 Google Authenticator의 **+ → 설정 키 입력**에서 이름을 `Gem-Codex 승인`, 유형을 **시간 기준**으로 선택해 등록합니다. 기존 GitHub 로그인용 OTP와 다른 항목입니다. 표시된 6자리 번호로 등록을 확인합니다. 등록에 사용한 번호는 승인에 재사용할 수 없습니다.

등록 키와 승인 이력은 이 컴퓨터의 `.approval-local/state.json`에 저장됩니다. 외부 QR 생성 서비스로 보내지 않습니다. 이 폴더는 Git에서 제외됩니다. 파일은 암호화되지 않으며 Windows에서는 파일 모드만으로 접근 차단을 보장하지 못하므로 공용 계정·공용 폴더에서 실행하지 마세요. AI 작업 환경과 승인 도구는 분리해서 사용합니다.

## 매번 승인

1. GitHub에 자동 생성된 초안 PR의 변경 내용과 협업 보고서를 확인합니다.
2. GitHub에서 **Ready for review**로 전환합니다. 이것만으로 병합되지 않습니다.
3. 승인 화면에 PR 번호를 입력하고 **PR 확인**을 누릅니다. 같은 저장소의 기본 브랜치로 향하는 PR만 허용합니다.
4. 검사 결과가 모두 성공해야 합니다. 봇이 만든 PR은 일반 CI 이벤트가 발생하지 않을 수 있어 자동화가 `Check automation`을 별도로 실행합니다. 이 기본 검사는 자동화 코드만 확인하므로 실제 앱을 추가하면 앱 테스트도 CI에 추가하세요.
5. 링크를 열어 변경 내용을 확인한 후 Authenticator의 새 OTP를 입력하고 **확인한 변경을 승인하고 반영**을 누릅니다.

승인은 확인한 head 커밋에 묶이며 5분 뒤 만료됩니다. head나 base가 바뀌면 다시 확인해야 합니다. GitHub 병합 API에도 head SHA를 보내 승인 후 변경된 head의 병합을 차단합니다. base 변경은 병합 직전 재확인하지만 API가 base SHA 조건을 제공하지 않아 엄격한 최신 기준 검증은 GitHub 보호 규칙이 추가로 필요합니다. 병합 방식은 squash입니다.

OTP는 현재 30초 구간과 직전 구간만 허용하며 사용한 구간은 재사용하지 않습니다. 5회 실패 시 5분 동안 차단합니다. 승인 후 GitHub가 병합을 거절해도 해당 OTP는 소비되므로 새 코드로 다시 시도하세요. GitHub 보호 규칙은 우회하지 않습니다.

비정상 종료 후 `server.lock` 오류가 나면 승인 프로세스가 실행 중이지 않은지 확인한 뒤 `.approval-local/server.lock` 파일만 직접 정리하세요. `state.json`은 삭제하면 OTP 등록과 재사용 방지 기록도 사라집니다.

실제 토큰 발급, OTP 등록, GitHub 연결, 실제 PR 반영은 아직 실행하지 않았습니다. 테스트는 표준 OTP 벡터·재사용 차단·버전 결속과 모의 협업 흐름을 검증합니다.
